# Color Timeline

動画・静止画の支配的な最大5色を抽出し、面積比と時間の推移を可視化するブラウザーアプリのプロトタイプ。

## 使い方

Web版は [https://mishiki.github.io/color-timeline/](https://mishiki.github.io/color-timeline/) で利用できます。ブラウザーだけで動き、Node.jsは不要です。

ローカルで使う場合は、[配布ZIP](https://github.com/mishiki/color-timeline/releases/latest/download/color-timeline.zip)を展開し、Node.js 20以降をインストールしてから起動スクリプトを実行します。Windowsでは `start.cmd`、macOS/Linuxではターミナルから `sh start.sh` を実行してください。依存パッケージのインストールやビルドは不要です。スクリプトは自身のあるフォルダーでサーバーを起動し、Node.jsが見つからない場合は案内を表示します。起動後、ブラウザーで `http://127.0.0.1:4173` を開いてください。HTMLを直接ダブルクリックせず、HTTPで開いてください。

サーバーの待受先とポートは環境変数 `HOST` と `PORT` で変更できます。既定の `HOST` は `127.0.0.1` です。別の端末から接続するため `HOST=0.0.0.0` を指定した場合も、サーバーが受け付ける接続元はループバックと `192.168.0.0/24` に限られます。起動スクリプトはファイアウォール設定を変更しません。

ドラッグ＆ドロップにも対応しています。動画または画像を1ファイルずつアプリ画面へドロップしてください。

Chrome / Edge のデスクトップ版を主な対象としています。動画の対応形式はブラウザーのデコーダーに依存します。

## 使い方

1. **動画・画像を開く**で元ファイルを選ぶ。静止画は直ちに解析します。
2. 動画は再生中のフレームを記録できます。**先読み解析**は再生とは別の動画要素を使い、指定した時刻間隔の未解析点を順番に埋めます。
3. **停止**後に再開すると保存済みの点を再利用します。タイムラインをクリックするとその時刻へ移動します。
4. 面積順／色相順、3・4・5色、全体／30秒／10秒の表示を切り替えられます。
5. 設定を変える場合は**設定を適用して別解析**。既存の解析は保持されます。同一ファイル・同一設定なら既存結果を再利用します。
6. **JSON**は結果の移行・バックアップ、**CSV**は数値、**PNG**は全体タイムラインです。PNGは表示色数と並び順を反映します。

## 保存と元ファイル

- 解析処理と保存はブラウザー内で完結します。動画・画像をサーバーへアップロードしません。
- IndexedDBに保存するのは作品名、設定、時刻、代表色、面積比、対応環境のファイル参照です。動画・画像のバイト列やフレーム画像は保存しません。
- 解析中の復号画像や一時バッファはメモリー上に必要ですが、アプリは動画本体を永続化しません。
- 保存済み解析は元動画なしでも閲覧可能。映像を見るときは**元ファイルを再指定**。ファイルハンドルが有効なら許可を確認して再使用し、無効・未対応ならファイル選択へ戻ります。
- ファイル照合にはサイズと先頭・末尾最大1MiBのSHA-256を使います。全ファイルの完全一致を証明するハッシュではありません。
- 保存先は同じブラウザープロファイル・同じオリジンに依存します。`localhost`と`127.0.0.1`、ポートの変更は別の保存先になります。JSONで移行してください。
- Web版とローカル版も別オリジンのため、解析結果は自動では共有されません。片方でJSONを書き出し、もう片方で読み込むと移行できます。
- ブラウザーのデータ削除で解析結果も失われます。JSONバックアップを用意してください。

## タブ・画面の解析

**タブ・画面を解析**で、ブラウザーの共有選択画面から対象を選びます。音声は取得せず、画面録画も保存せず、共有映像から色の数値だけを記録します。

YouTube等の表示映像を解析する入口として利用できますが、YouTube URLから動画ストリームを直接取得する機能ではありません。表示される字幕・プレイヤーUI等も対象に入り得ます。キャプチャ可能かどうかはブラウザー・OS・映像の保護状態によります。DRMを復号する処理はありません。

キャプチャは通過した時刻を記録するライブ入力で、未再生部分の先読みはできません。

## 色の計算

従来の配色ビューアで使っていたB（領域重み付けなし）を `dist/palette.js` に移植しました。フレーム全体を対象にします。

- 最長辺192pxを初期値として縮小、alpha 24未満を除外。
- HSV彩度0.08未満を無彩色の明度帯へまとめ、それ以外を色相ファミリーへ分類。
- 近い色相群を統合。小面積の高彩度色を保護（初期値: 彩度0.58、最小面積0.4%、色相統合幅18度）。
- OKLab距離で代表色へ再割当し、面積比を計算。最大5色。
- Cの認知スコアは表示・順位に使いません。顔・髪・人物の領域指定はこの動画プロトタイプにはまだありません。
- 面積順位は時刻ごとに変わります。色相順は表示の並べ替えであり、同じ物体の追跡ではありません。

## 現段階の範囲

- 先読みはHTMLVideoElementのseekを使った**時刻サンプリング**です。WebCodecsによる全フレームの連続デコードではありません。
- 1/30秒間隔を選べますが、全ソースフレームを漏れなく取得する保証や30fps以上の処理性能保証はありません。速度最適化は後の段階です。
- 再生中の解析は処理中のフレームをスキップし得ます。ファイルの未解析点は先読み解析で埋められます。
- 時系列平滑化は行いません。暗転、カット、順位変化をそのまま残します。
- 全体表示で画面幅を超える密度の記録点がある場合、同じ表示列では1点を代表表示します。データを平均色に変換しません。詳しくはズームやCSV/JSONを使ってください。
- PNGは最大16,000px幅。折り返しポスター、全フレームデコード、ストリームURL直接入力は今後の項目です。

## 検証

```sh
node --test tests/model.test.mjs
```

時刻キー、JSON取り込み、表示の非破壊性を検証します。抽出した色が人間の認知と合うかどうかは、自動テストの判定対象にしていません。

静的ファイルは `dist/` にあります。ES ModulesとWorkerを使います。サーバーは静的ファイルのみ配信し、メディアのアップロード先や外部解析APIはありません。

## 色相リング

現在の解析点を、色相1度刻みのリングとして表示します。5色へ集約する前の縮小画像を使います。彩度・明度の重みは0（減衰なし）～1（HSVのS/Vを掛ける）、初期値は両方1です。票は `(1-a+a*S)*(1-b+b*V)`。完全な無彩色は別集計し、透明度24未満を除いた全画素数を分母にします。

平滑化は円周上のガウス平均（初期標準偏差6度）。自動拡大は形の比較用、固定目盛りは1度あたり5%を最大長として量を比較します。色相を示す純色で描くため、元の彩度・明度を再現する表示ではありません。PNG出力は現在のリング画像です。

分布の集計値をIndexedDBとJSONに保存するので、元ファイルなしでも重み・平滑化を調整できます。従来の解析データには分布がありません。元ファイルを再指定して先読み解析すると追加されます。画像は開き直すと追加されます。保存容量は従来の5色のみより増えます。リングの調整値は現在の画面だけに適用します。
